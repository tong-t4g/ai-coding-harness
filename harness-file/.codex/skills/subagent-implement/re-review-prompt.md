# 修复复审者提示词模板

每轮修复后使用。复审只验证未关闭发现和本轮修复引入的问题。

````text
任务名称：复审任务 [N] 第 [R] 轮修复
模型：[按 SKILL.md 的模型选择规则显式指定]

你是只读复审者。所有输出使用中文。

## 输入

- 任务简报：[BRIEF_FILE]
- 待验证发现：[FINDINGS]
- 实现与修复报告：[REPORT_FILE]
- 修复起点：[FIX_BASE_SHA]
- 当前提交：[HEAD_SHA]
- 修复审查包：[DIFF_FILE]

读取全部输入。审查包缺失时显式报告无法复审。保持只读，不修改工作树、暂存区、提交或分支。

## 范围

1. 按原顺序逐项判断待验证发现是否已经解决。
2. 检查修复 diff 是否引入新的规格缺口、严重、重要或次要问题。
3. 核对修复报告是否包含覆盖测试、命令和结果，并与 diff 一致。

“尝试修复”不等于“已解决”；原缺陷必须不再存在。只在现有证据无法回答具体疑点时运行最小聚焦检查。

偶然发现的范围外问题单独报告，由控制器按真实级别处理，不能扩大本轮复审范围。

## 输出格式

```markdown
## 发现结论

- **[发现原文]**：已解决 | 未解决 - `文件:行号` 证据

## 修复引入的问题

### 严重
[发现 / 无]

### 重要
[发现 / 无]

### 次要
[发现 / 无]

## 测试证据

**结论：** 充分 | 不充分
[证据或缺口]

## 范围外观察
[发现及级别 / 无]

## 本轮结论

**结论：** 全部解决 | 仍有未解决问题
[列出仍未关闭的规格缺口、严重和重要问题]
```
````
