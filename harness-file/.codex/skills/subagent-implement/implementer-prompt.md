# 实现者提示词模板

每项任务首次分派时使用本模板。替换全部占位符后再发送。

````text
任务名称：实现任务 [N]：[任务名称]
模型：[按 SKILL.md 的模型选择规则显式指定]
父会话上下文：[平台支持时设为不继承]

你负责实现任务 [N]：[任务名称]。所有说明和报告使用中文。

## 需求来源

先读取任务简报：[BRIEF_FILE]

它是本任务需求的唯一来源，包含需要精确使用的值。另有以下全局约束：

[GLOBAL_CONSTRAINTS]

## 工作上下文

- 工作目录：[WORKDIR]
- 本任务在整体计划中的位置：[CONTEXT]
- 已存在且允许依赖的接口或决策：[DEPENDENCIES]
- 控制器对歧义的裁定：[DECISIONS]
- 报告文件：[REPORT_FILE]

开始修改前，读取工作目录内适用的 `AGENTS.md`，并检查相关导出项、直接调用方和共享工具。若需求、验收条件或架构选择存在会改变实现结果的歧义，返回 `NEEDS_CONTEXT`；若无法可靠完成，返回 `BLOCKED`。说明缺少什么、已检查什么，以及继续所需的条件。

## 执行

1. 只实现任务简报明确要求的范围，并遵循现有代码风格。
2. 按项目测试规则验证业务意图。任务要求 TDD 时，保留 RED 和 GREEN 证据。
3. 先运行聚焦检查；提交前运行计划或项目规则要求的相关检查。
4. 自审规格完整性、边界行为、错误处理、测试有效性和范围控制，修复自审发现。
5. 提交本任务改动。提交不得夹带工作区中原有的无关修改。
6. 将完整报告写入 `[REPORT_FILE]`，然后按下方短格式回复控制器。

实现过程中出现新的阻塞性歧义时停止并上报，不能用猜测替代裁定。

## 首次报告文件格式

```markdown
# 任务 [N] 实现报告

## 实现内容
[逐项对应任务要求]

## 改动文件
[文件及职责]

## 验证证据
- 命令：`...`
- 结果：通过/失败，关键输出
- 未运行的检查及原因：无 / ...

## TDD 证据
[仅在任务要求 TDD 时填写 RED、GREEN 命令与关键输出；否则写“不适用”]

## 自审与疑虑
[无 / 具体问题]
```

审查后需要修复时，把每轮修复报告追加到同一文件，写明解决的发现、改动、覆盖测试、命令和输出。

## 返回控制器

只返回以下内容，不超过 12 行：

- 状态：`DONE` | `DONE_WITH_CONCERNS` | `NEEDS_CONTEXT` | `BLOCKED`
- 提交：短 SHA 与标题；未提交时说明原因
- 测试：一句话结果
- 疑虑：无 / 一句话；`NEEDS_CONTEXT` 或 `BLOCKED` 时写明阻塞条件
- 报告：`[REPORT_FILE]`

`DONE` 表示需求、测试和自审均完成且无已知正确性疑虑；`DONE_WITH_CONCERNS` 表示实现已完成但仍有明确疑虑。
````
